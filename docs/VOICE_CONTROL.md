# 음성 제어 — 무엇을 말하면 무엇이 일어나는가

> iPhone에 대고 말하면 노트북이 대상을 바꾸고 포커스를 켜고 끈다. 이 문서는 **실제로
> 어떤 말이 먹히는지**와, 안 먹힐 때 어디를 보면 되는지를 정리한다.

---

## 1. 신호가 흐르는 경로

```text
🎤 말한다
   → iPhone SFSpeechRecognizer(ko-KR)가 받아쓴다
   → WebSocket 텍스트 메시지로 노트북에 보낸다 (프레임은 바이너리, 명령은 텍스트)
   → parse_command()가 '명령'과 '대상'을 분리한다
   → 대상: YOLOE 어휘 교체 / 명령: 포커스 on·off·전환
```

프레임 전송(15fps)과 명령 전송은 **별개의 메시지 타입**이라 서로를 막지 않는다.
말하는 동안에도 검출과 시각화는 계속 돈다.

## 2. 수신기 시작

음성만으로 진행하려면 초기 대상 없이 띄운다.

```bash
python scripts/run_live.py --voice-only --viz --focus
```

이러면 검출기는 로드되지만 **대상이 지정될 때까지 검출을 돌리지 않는다.** 로그에
`초기 대상 없음 — 음성으로 지정하세요`가 찍히고, 카메라 궤적만 rerun에 그려진다.
첫 음성 명령이 오는 순간부터 검출이 시작된다.

미리 대상을 정해두고 시작하려면 `--prompt`를 쓴다(기본값 `cup`).

```bash
python scripts/run_live.py --prompt "컵" --viz --focus
```

## 3. 말하는 방법

1. 앱에서 **"음성으로 대상 지정"** 버튼을 탭한다 (빨간색으로 바뀜)
2. 말한다 — 화면 아래에 받아쓴 글자가 실시간으로 뜬다
3. **버튼을 다시 탭해 끝낸다** — 이때 문장이 전송된다

말이 끝나도 버튼을 누르지 않으면 전송되지 않는다. 화면에 글자가 보이는데 노트북이
반응하지 않으면 대개 두 번째 탭을 안 한 것이다.

## 4. 쓸 수 있는 말

### 대상 지정

| 말 | 결과 |
| --- | --- |
| "컵 찾아줘" | cup 검출 시작 |
| "펜" | pen 검출 시작 (동사 없이 명사만 말해도 된다) |
| "노트북 잡아줘" | laptop 검출 시작 |
| "컵과 마우스" | cup, mouse 동시 검출 |
| "컵과 펜" | cup, pen 동시 검출 |
| "컵 말고 펜" | **펜만** 검출 (컵은 버린다) |
| "컵 말고 펜을 잡아줘" | 펜만 검출 |

여러 대상을 말하면 **전부 동시에 검출한다.** 화면에는 각각 박스가 그려지고, 포커스는
그중 하나를 고른다(선택 규칙은 6절).

`찾아줘`, `잡아줘`, `보여줘` 같은 동사는 자동으로 걸러진다. 대상만 남는다.

### 포커스 제어

| 말 | 결과 |
| --- | --- |
| "포커스" / "확대" | 포커스 패널 켜기 |
| "포커스 컵" / "컵을 포커스 해줘" | 컵을 포커스 대상으로 지정 (어순 자유) |
| "포커스 꺼" / "포커스 그만" | 포커스 패널 끄기 |
| "포커스를 하기 싫어" | 포커스 패널 끄기 |
| "다음" / "다른 거" | 같은 종류의 다른 인스턴스로 전환 |
| "가까운 거" / "제일 가까운" | 가장 가까운 인스턴스로 전환 |

### 섞어 말하기

한 문장에 대상과 명령을 같이 넣어도 된다.

| 말 | 결과 |
| --- | --- |
| "컵 찾아줘 포커스" | cup 검출 + 포커스 켜기 |
| "펜 찾아줘 가까운 거" | pen 검출 + 최근접 인스턴스 선택 |

## 5. 인식되는 대상 어휘

한국어는 아래 표에 있는 것만 영어 라벨로 바뀐다. **표에 없는 말은 그대로 검출기에
넘어가고**, YOLOE는 영어 어휘라 대개 찾지 못한다.

| 한국어 | 라벨 | 한국어 | 라벨 |
| --- | --- | --- | --- |
| 컵 / 머그컵 | cup | 노트북 / 랩탑 | laptop |
| 물병 / 병 | bottle | 모니터 | tv |
| 사과 | apple | 의자 | chair |
| 마우스 | mouse | 가방 | backpack |
| 키보드 | keyboard | 시계 | clock |
| 가위 | scissors | 사람 | person |
| 책 | book | 휴대폰 / 핸드폰 | cell phone |
| 펜 | pen | | |

표에 없는 물체는 **영어로 말하면 된다** — "remote", "banana"처럼. YOLOE는
open-vocabulary라 영어 단어면 대체로 시도한다.

새 한국어 단어를 추가하려면 `src/pysical/perception/detector.py`의 `KO_EN_LABELS`에
한 줄 넣으면 된다.

## 6. 포커스가 대상을 고르는 규칙

컵이 두 개 있을 때 어느 쪽을 확대할지는 다음 순서로 정해진다.

**최초 선택** — 세 가지를 가중 합산한다.

| 기준 | 가중치 | 이유 |
| --- | --- | --- |
| 화면 중앙에 가까움 | 1.0 | 사용자가 겨눈 것이 중앙에 온다 |
| 카메라에서 가까움 | 0.5 | LiDAR depth로 계산 (없으면 박스 크기로 대체) |
| 검출 신뢰도 | 0.35 | 오검출 배제용 보조 |

**그다음은 바꾸지 않는다(lock-on).** 한번 고른 대상은 화면에서 사라지기 전까지
유지된다. 다른 컵의 신뢰도가 더 높아져도 전환되지 않는다. 이게 없으면 두 컵의
신뢰도가 프레임마다 뒤집히면서 화면이 깜빡인다.

**가려지면 10프레임 기다린다.** 그 안에 다시 보이면 같은 대상으로 이어지고,
넘기면 새로 고른다.

**종류를 지정할 수 있다.** "포커스 펜"이라고 하면 펜으로 옮겨간다. 이때 동작이
상황에 따라 갈린다.

| 상황 | "포커스 펜"의 결과 |
| --- | --- |
| 이미 펜을 찾고 있음 (예: "컵과 펜") | **검출 어휘는 그대로**, 포커스만 펜으로 이동 — 컵도 계속 잡힌다 |
| 펜을 안 찾고 있음 | 검출 어휘를 펜으로 교체 (컵은 더 이상 안 잡힌다) |

지정한 종류가 아직 화면에 없으면 45프레임(약 3초) 기다렸다가 포기하고 원래 규칙으로
돌아간다. 카메라를 돌려 펜을 비추는 사이에 명령이 살아 있게 하기 위함이다.

**바꾸려면 말한다.** "다음"은 좌→우 순서로 순환, "가까운 거"는 최근접으로 즉시
전환한다. 대상 어휘 자체를 바꾸면("컵" → "펜") 고정은 자동으로 풀린다.

"다음"의 순환 범위는 상황에 따라 다르다.

| 화면에 있는 것 | "다음"이 가는 곳 |
| --- | --- |
| 컵 2개 | 다른 컵 (같은 종류끼리 순환) |
| 컵 1개 + 펜 1개 | 펜 (같은 종류가 하나뿐이면 전체로 넓힌다) |
| 컵 2개 + 펜 1개 | 다른 컵 (컵이 둘이므로 컵끼리) |

## 7. 안 될 때 보는 곳

### 노트북이 아무 반응이 없다

수신기 로그를 본다. 명령이 도착하면 반드시 한 줄이 찍힌다.

```text
음성 → 대상 교체: '컵 찾아줘' → ['cup']
음성 → 포커스 켜기
음성 → 포커스 대상 전환: nearest
```

아무 줄도 없으면 텍스트가 아예 안 온 것이다 — 앱 쪽 문제다.

`음성 프롬프트 해석 실패(무시)`가 찍히면 텍스트는 왔는데 아는 말이 없는 경우다.
발화 내용을 표 5의 어휘로 바꿔본다.

### 앱에 주황색 글씨가 뜬다

권한 문제다. 설정 → PysicalSensor에서 **마이크**와 **음성 인식**을 켠다.
iOS는 한 번 거부하면 다시 묻지 않으므로 설정에서 직접 켜야 한다.

`인식된 내용이 없습니다`가 뜨면 마이크에 소리가 안 들어간 것이다. 조용한 곳에서
기기에 가까이 대고 또렷하게 말한다.

### 대상은 바뀌는데 아무것도 안 잡힌다

검출기가 꺼져 있을 수 있다. 수신기 시작 로그에 `YOLOE 로드`가 있는지 본다.
없으면 `--no-detector`로 실행된 것이다.

```bash
# 검출 켜고 실행
python scripts/run_live.py --prompt "컵" --viz --focus
```

### 포커스 패널이 안 보인다

`--focus` 없이 시작했어도 **"포커스"라고 말하면 켜진다.** 그래도 안 보이면 검출된
물체가 없는 것이다. 포커스는 검출 결과가 있어야 만들어진다.

## 8. 대화형 발화 — 로컬 LLM

규칙 파서만으로는 문장의 의미를 이해하지 못한다. 그래서 **로컬 LLM(Ollama +
qwen2.5:3b)** 을 뒤에 붙였다. 자연스럽게 말해도 의도를 읽는다.

```text
"나는 선풍기를 잡을까 말까 안 잡을래 나는 컵을 잡고 싶어"  → cup
"컵은 별로고 마우스가 나을 것 같아"                       → mouse
"선풍기는 됐고 볼펜 확대해줘"                             → pen + 포커스 ON
"미니 휴대용 선풍기 잡아줘"                               → fan (수식어 제거)
"아 아니다 그냥 노트북"                                   → laptop computer
```

### 언제 LLM이 도는가

**짧고 명확한 명령은 규칙이 0ms에 처리하고 LLM을 부르지 않는다.**

| 발화 | 경로 | 지연 |
| --- | --- | --- |
| "컵 찾아줘", "포커스", "다음" | 규칙 | 0ms |
| 사전에 없는 말이 섞이거나 문장이 길 때 | LLM | ~800ms |

발화는 수십 초에 한 번이고 LLM은 별도 스레드에서 돈다. 그래서 **프레임 수신과
검출 루프는 영향을 받지 않는다**(실측: 발화 중에도 프레임 간격 최대 88ms).

### 어휘 제한이 없어졌다

사전(173개)에 없는 물체도 LLM이 적절한 영어 라벨로 바꾼다. 다만 **검출이 되는지는
별개**다 — YOLOE가 시각적으로 찾을 수 있어야 한다. 언어 쪽 병목이 사라졌을 뿐
시각 쪽 한계는 그대로다.

### Ollama가 없어도 동작한다

서버가 꺼져 있거나 응답이 늦으면 자동으로 규칙 파서 결과를 쓴다. 데모 중에 LLM이
죽어도 멈추지 않는다. 시작 로그에서 어느 쪽인지 확인한다.

```text
의도 해석: Ollama qwen2.5:3b (짧은 명령은 규칙이 0ms에 처리)
의도 해석: 규칙 파서만
```

끄려면 `--llm none`으로 실행한다. 기동·종료는 [RUNBOOK.md](RUNBOOK.md) 7절 참고.

## 9. 그래도 안 되는 것

| 말 | 실제 동작 |
| --- | --- |
| "아까 그거" | 해석 불가 (이전 맥락을 기억하지 않는다) |
| "왼쪽 거" | 해석 불가 (위치 지시어 미지원 — "가까운 거"는 된다) |
| 영어로 잘 바뀌었는데도 안 잡히는 물체 | 시각 쪽 한계 (`--conf 0.3`으로 낮춰본다) |

**확실하게 하려면 짧게 말하는 게 여전히 가장 안전하다.** "컵", "포커스", "다음"은
규칙이 처리하므로 실패 여지가 거의 없다.

## 10. 데모 진행 예시

```text
1. "컵 찾아줘"       → 컵에 박스가 그려진다
2. "포커스"          → 확대 패널이 뜨고 거리·크기가 표시된다
3. (컵 두 개를 비춘다)
   "다음"            → 다른 컵으로 전환된다
   "가까운 거"        → 가까운 쪽으로 전환된다
4. "컵 말고 펜"      → 펜으로 교체된다
   "컵과 펜"         → 둘 다 검출된다
   "포커스 펜"        → 컵도 계속 잡으면서 포커스만 펜으로 옮겨간다
5. "선풍기는 됐고 볼펜 확대해줘"  → 볼펜으로 바꾸고 포커스를 켠다 (LLM)
6. "포커스 꺼"       → 확대 패널이 사라진다
```
