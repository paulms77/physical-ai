# Focus-and-Refine — 화질 전처리와 검출 정확도 실측

> "AI 모델이 픽셀을 어떻게 보는지 알면, 전처리로 검출을 개선할 수 있지 않나?"
> 라는 질문에서 출발한 실험과 그 결론. 이 프로젝트의 검출 정확도 차별점의 근거다.

---

## 1. 문제 — 모델은 이미지를 '축소해서' 본다

검출 모델(YOLOE)은 원본을 그대로 보지 않고 고정 크기(예 640×640)로 **축소**해서
본다. 그래서 화면에서 작은/멀리 있는 물체는 몇십 픽셀로 뭉개져 신뢰도가 낮아진다.

```
원본 1166×874                모델이 보는 640×640
  🖱️ 작은 마우스(36×61px)  →  ~20×34px 로 뭉개짐 → "자신 없음" (conf 0.22)
```

## 2. 실험 — desk.jpeg의 작은 마우스로 측정

작은 마우스(신뢰도 0.22)를 영역만 잘라 여러 전처리 후 재검출했다.

| 전처리 | mouse 신뢰도 | 판정 |
|---|---|---|
| 원본(전체 화면) | 0.219 | 기준 |
| 크롭만(확대 없이) | 0.316 | 살짝↑ |
| **크롭 + 2~3x 확대(cubic)** | **0.51 ~ 0.61** | ✅ **2~2.8배↑** |
| 크롭 + 4x 확대 | 0.16 | ❌ 과확대는 나쁨 |
| 크롭 + 확대 + **선명화(sharpen)** | **0.000** | ❌ 치명적 |
| 크롭 + 확대 + **CLAHE 대비향상** | **0.000** | ❌ 치명적 |

## 3. 결론 — "고화질"이 아니라 "모델의 눈높이"

세 가지 교훈이 나왔다. 이게 질문에 대한 답이다.

1. **적당한 확대는 이롭다.** 작은 물체를 모델이 학습한 크기대로 되돌리면 신뢰도가
   2배 이상 오른다. 당신의 직관(영역을 키워서 잡자)이 맞았다.

2. **과도한 확대(4x)는 해롭다.** 무작정 크게가 아니다. 물체가 모델이 편하게 보는
   크기대(~100~150px)를 넘어가면 오히려 나빠진다.

3. **선명화·CLAHE 같은 '보정'은 치명적이다(0.000).** 사람 눈엔 선명해 보여도
   모델에겐 독이다. **모델은 학습 데이터의 통계 분포로 본다.** 인위적 엣지 강조나
   대비 왜곡은 그 분포를 벗어나게 만들어 "낯선 노이즈"가 된다.

> 핵심 통찰: 목표는 **'고화질'이 아니라 '물체를 모델이 학습한 크기·통계로 되돌리는
> 것'**이다. 그래서 배율을 물체 크기에 맞춰 **적응적**으로 정한다(refine.py의
> `adaptive_upscale_factor`). 이미 큰 물체는 확대하지 않는다.

## 4. Focus-and-Refine 파이프라인

```
1차: 전체 화면 저해상 스캔 → 후보 위치(낮은 신뢰도라도)
        ↓  (신뢰도 낮은 것만 선택 — 큰 물체는 그대로 둠)
2차: 후보 영역만 잘라 적응적 배율로 확대 → 재검출
        ↓
결과: mouse 0.22 → 0.61 (실측). 좌표는 전체 이미지 기준으로 복원.
```

구현: `src/pysical/perception/refine.py` (`refine_detection`, `refine_all`)

## 5. 의료 워크플로와의 대응

이 2단계는 초음파/영상 진단의 표준 절차와 같다.

| Focus-and-Refine | 의료 영상 |
|---|---|
| 전체 저해상 스캔으로 후보 찾기 | 광역 스캔으로 의심 부위 찾기 |
| 후보 영역만 적응적 확대 재검출 | 의심 부위를 확대·정밀 스캔 |
| 신뢰도↑ + 정밀 마스크 | 병변 경계 세밀화 |

지금은 병변 대신 일반 객체로 '기능'을 증명한다. 나중에 대상만 병변으로 바꾸면
그대로 의료 버전이 된다.

## 7. 학습기반 SR(ESPCN) 적용 — "고화질 유지 확대"의 답

단순 보간(CUBIC)은 작은 영역을 키우면 뭉개진다("화질이 깨진다"). 해결책은 **학습기반
super-resolution**이다. 같은 작은 mouse를 x3 확대해 비교했다(실측):

| 방법 | 선명도(라플라시안↑) | 검출 신뢰도 | 속도(CPU) |
|---|---|---|---|
| CUBIC (단순 보간) | 11.4 | 0.10 | 즉시 |
| LANCZOS4 | 11.3 | 0.00 | 즉시 |
| **ESPCN x3 (학습기반 SR)** | **15.4 (+35%)** | **0.34 (3.3배)** | **~74ms** |

시각적으로도 ESPCN이 마우스 윤곽·배경 손글씨까지 또렷하게 복원했다(data/sr_compare.jpg).

**왜 SR은 되고 선명화(§3)는 안 되나.** 선명화/CLAHE는 인위적 엣지·대비로 모델의 학습
분포를 벗어나게 만들어 해로웠다(0.000). 반면 SR은 **학습으로 자연스러운 디테일을 복원**
하므로 분포를 해치지 않는다. 즉 "고화질"의 올바른 구현은 필터가 아니라 SR이다.

**적용.** `src/pysical/perception/upscale.py`의 `Upscaler`(ESPCN, OpenCV dnn_superres).
refine.py와 focus.py의 확대를 CUBIC → ESPCN으로 교체. 모델은 GitHub
(fannymonori/TF-ESPCN)의 ESPCN_x2/x3/x4.pb(~90KB, 사내망 GitHub 정상). 모델이 없으면
CUBIC으로 자동 폴백. opencv-contrib-python 필요(dnn_superres 포함).

레퍼런스: SR 전처리가 소형 객체 검출 mAP를 x2에서 +13.4% 올린다는 연구(Sensors 2024,
Springer 2024)와 일치. ESPCN은 실시간용 경량 SR로 OpenCV에 내장(learnopencv, OpenCV docs).

## 8. 더 나아갈 여지 (선택)

- **더 강한 SR**: SPAN/RLFN(ONNX)·Real-ESRGAN. 화질↑이나 CPU 비용↑ — A6000 오프라인용.
- **타일링/SAHI**: 큰 이미지를 격자로 잘라 각각 원해상도 검출 후 합치기. Focus-and-Refine과 상호보완.
- **입력 해상도(imgsz) 상향**: 640→960/1280. 전역적이지만 CPU 비용↑.
